# ### 1. Core Concepts (Why We Do What We Do)

# | Concept | What it is | Why we use it |
# |---------|------------|---------------|
# | **Authentication** | "Who are you?" (login → token) | Proves identity |
# | **Authorization (RBAC)** | "What are you allowed to do?" (check role) | Role-Based Access Control |
# | **JWT (JSON Web Token)** | Tiny signed string containing `user_id`, `role`, `expiry` | **Stateless** → no database lookup on every request (fast + scalable). Can't be faked because it's cryptographically signed. |
# | **Password Hashing (Argon2)** | Never store plain password | If DB leaks, attacker still can't log in |
# | **OAuth2PasswordBearer** | FastAPI's built-in way to read `Authorization: Bearer <token>` header | Auto-generates beautiful login button in `/docs` |
# | **Dependencies (`Depends`)** | Reusable functions FastAPI calls automatically before your route runs | Write security logic **once**, use everywhere. Clean code. |
# | **Current User Dependency** | Gets the logged-in user (or raises 401/403) | Every protected route just does `current_user: User = Depends(get_current_user)` |

# ### 10. Why This Design Is Great for Beginners

# - Every security decision is **visible** in the dependency chain.
# - Adding a new role later is just adding to the `Role` enum + new `require_role("moderator")`.
# - You now **understand** every line instead of copy-pasting a black-box library.
